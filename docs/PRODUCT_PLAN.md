# 嬷嬷模拟器（momomoniqi）产品实施 Plan

> 把你最严肃的角色，宠成全网嬷嬷。

## 1. 产品定位与改进后的核心玩法

### 1.1 定位

「嬷嬷模拟器」是一个**纯前端的整活式互动玩具 + DIY 同人二创社区**：用户把任何严肃/高冷/威严的角色图（宫斗剧嬷嬷、老板头像、班主任、自家猫）丢进来，系统把它像素化成一只"电子嬷嬷"，然后用摸摸头、rua、哄睡、丢球等动作**过度宠溺**它——玩法灵感来自拓麻歌子（Tamagotchi）：电子宠物式养育（精力/亲密度）+ 粉丝同人二创展台。养出来的嬷嬷可以生成"认证卡"发社媒，也可以**过审后发布到社区展台**，被其他玩家点赞、点彩。

### 1.2 对初始设想的改进

| 初始设想 | 改进落地 |
| --- | --- |
| "导入角色模板并做动画" | 收敛为**中心裁切 + 像素化 + 调色板风格化**的确定性管线，10 秒内出结果，零后端、零等待，任何图都能出效果（不依赖 AI 生成的不确定性） |
| "支持社媒热点互动（摸摸头）" | 抽象成**动作系统**：7 个动作 × 随机文案池 × 暴击机制 × 养育数值影响，动作可持续追加以蹭新热点 |
| "搞笑元素" | 结构化为三层：**反差文案**（严肃角色被宠到破功）+ **离谱数值**（嬷力值、12% 概率暴击 +66）+ **成就体系**（见习小嬷嬷 → 宇宙第一嬷） |
| "形成爆火效应" | 双传播出口：**站外**认证卡 PNG + 话题文案；**站内**社区展台（DIY 作品 feed + 点赞/点彩），种子作品保证首访有内容可刷 |
| "DIY 自创传播" | 拓麻歌子同人二创范式：养育循环产生情感投入 → 发布到展台获得关注 → 浏览他人作品激发"我也要做一只" |

### 1.3 核心循环（Core Loop）

```
上传角色图 → 像素化/风格化实时预览（7 种风格）
    → 选动作互动（摸头 / rua / 拍拍 / 喂食 / 哄睡 / 夸夸 / 丢球）
    → 动画 + 音效 + 粒子/彩屑/震屏 + 无厘头文案 + 嬷力值增长 + 养育数值（精力/亲密度）变化
    → ①生成"嬷嬷认证卡" PNG / 复制文案 → 发社媒 → 引来新用户
    → ②填写标题/昵称/简介 → 内容审核 → 过审上架社区展台 → 被点赞/点彩 → 激发他人 DIY
```

单次循环 < 60 秒，无注册、无等待，符合"刷到 → 玩到 → 转发/发布"的短链路传播。

## 2. 目标用户与传播机制（为何能爆）

### 2.1 目标用户

- **梗文化重度用户**（小红书 / 微博 / 抖音）：本来就在转发"公公嬷嬷"类魔性内容，需要低门槛的二创工具。
- **粉丝二创群体**：想对自家偶像/角色"下手"但不会 PS/AE 的人——社区展台就是他们的同人展位。
- **拓麻歌子怀旧党**：拓麻液晶风格 + 养育数值直接对标电子宠物情怀。
- **摸鱼社交党**：把老板/同事头像做成嬷嬷卡在群里传播。

### 2.2 传播机制

1. **反差即笑点**：越严肃的原图，被摸头 + "头顶已包浆"文案宠溺后反差越大——用户上传的图本身就是内容燃料，供给无限。
2. **产物自带钩子**：认证卡上有嬷力值、段位、无厘头语录和品牌名，看到卡的人会想"我也要给 XX 办一张"。
3. **社区展台闭环**：DIY 作品被点赞/点彩产生站内正反馈，养育数值产生情感沉淀，二者共同拉高留存与再创作率（拓麻歌子同人社群的经典循环）。
4. **数值攀比**：嬷力值、暴击、段位天然形成"晒分"心理；"宇宙第一嬷"是可截图炫耀的社交货币。
5. **热点可插拔**：新梗出现时只需向文案池 / 动作数组加数据（`src/data/quips.ts`），当天即可跟上热点。

## 3. MVP 功能范围 / 非目标

### 3.1 范围内（本仓库已实现）

**一期（工坊基础）**

- 落地首屏（品牌强信号 + 双 CTA：立刻开嬷 / 逛社区 + 像素嬷嬷主视觉）
- 图片上传：拖拽 / 点击选择，全程浏览器本地处理
- 像素化管线：颗粒度 16–96 格可调
- 嬷力值仪表、5 级成就、认证卡 PNG 分享、最近模板 localStorage

**二期（DIY 社区 / 风格化 / 互动升级）**

- **7 种风格预设**：像素原味 / 复古掌机 / 赛博粉 / 墨水印 / **拓麻液晶**（三阶灰绿屏）/ **贴纸手账**（粉彩）/ **黑白漫画**（1-bit 网点）
- **7 个互动动作**：摸摸头 / rua / 拍拍 / 喂食 + **哄睡 / 夸夸 / 丢球**（拓麻式），各配专属角色形变动画 + 道具入场动画 + 粒子
- **养育状态面板**：精力 / 亲密度两条像素数值条，动作影响数值（喂食哄睡回精力、玩耍涨亲密耗精力），派生心情文案
- **声音**：全部动作 / 暴击 / 点赞 / 点彩 / 发布 / 审核拒绝均有 Web Audio 现场合成的 8-bit 音效，零音频文件；全局静音开关（持久化）
- **画面特效**：暴击震屏 + 白闪、动作像素彩屑、点彩彩色粒子爆发
- **社区展台（本地模拟）**：发布流程（标题/昵称/简介 → 强制审核 → 上架）、feed 卡片（缩略图/嬷力值/段位/风格）、点赞（可切换）、点彩（累加 + 彩屑动画）、全部/我的过滤、5 条内置种子同人作品
- **审核机制**：发布前强制客户端黑名单过滤（政治敏感 / 公众人物敏感称呼 / 侮辱 / 低俗色情 / 违法违规五类），命中即拒绝并高亮类别，未过审无法发布
- **免责声明**：统一组件，固定出现在页脚、发布弹窗、社区页顶部
- 顶部粘性导航（工坊 ⇄ 社区 + 静音开关），移动端单列 feed + 大触控区

**三期（工作台升级：解析流水线 / 强互动 / 出卡 / 配方）**

> 设计依据（2026-08 调研）：拓麻歌子借 Y2K 怀旧翻红且「装扮化」成为社交单品；AI 宠物拟人反差短剧在抖音/小红书爆量；抖音「互动空间广场」与小红书「小工具 / vibecoding 榜」把「用户自制可玩内容 + 晒配方」推成平台级趋势；海外 OC 角色档案卡（character sheet）模板病毒式传播。以下功能为对应趋势的**原创**落地，不复用任何具体 IP 机制与命名。

- **幕后抠图**：Canvas 启发式背景去除（边缘取样聚类 + 四边泛洪 + 残点蚀刻 + 包围盒居中），上传图 → 透明底角色立绘；容差可调，失败自动回退；真实 AI 分割接口预留（`utils/cutout.ts`）
- **入嬷登记 / 自动解析**：图像哈希稳定种子 + 色彩统计（主色谱 / 高冷 / 活泼指数）+ 文件名关键词 → 体质谱系（宫廷 / 职场 / 兽形 / 师门 / 玄学）→ 生成名号 / 人设标签 / 反差设定 / 口头禅 / 档案声线；解析流水线五步动画 + 盖章音效强化仪式感；「换一卦」种子偏移重推（`utils/analyze.ts` + `data/persona.ts`）
- **嬷语开麦**（第 8 动作）：按档案声线（威严低音炮 / 碳酸气泡音 / 砂纸烟嗓 / 丝绸电台音 / 像素精灵音）用 Web Audio 合成怪声嘟噜语，字幕气泡带「官方翻译」（`utils/voice.ts`）
- **直戳互动**：点角色本体三分区（顶戴 / 面门 / 衣摆）反应 + 900ms 连击窗口（5/10/20 连里程碑）+ 长按捏住彩蛋，怪声音高随连击走高
- **伪 3D 舞台**：鼠标视差倾斜 + 角色/粒子景深分层（纯 CSS 3D，零引擎、移动端自动关闭）
- **贴纸装扮**：12 款贴纸点选上台 / 点击摘除 / 撤销清空，出卡叠印
- **出卡工作室**：三套 900×1200 竖版模板（认证卡 / 反差对比卡 / 嬷嬷档案卡），3D 倾斜 + 翻面预览（背面品牌纹），模板专属传播文案
- **配方工作流**：「抠图 → 风格 → 贴纸 → 出卡模板」存为可复用配方（localStorage），一键再跑；可发布为社区**玩法配方帖**
- **社区双内容**：feed 支持作品帖 + 玩法配方帖，配方帖展示链路摘要并可**一键套用**（跳回工坊重跑整条流水线）；筛选升级为全部 / 作品 / 玩法配方 / 我的；新增 2 条配方种子帖（老用户 feed 自动补播）

**社区本地化说明**：MVP 的"社区"是**本地模拟**——feed、点赞、点彩全部持久化在当前浏览器 localStorage，配合内置种子作品营造社区氛围，用于验证"DIY → 发布 → 被看见"的产品循环。跨设备真实社区需要后端（见 §7 迭代路线）。

### 3.2 非目标（MVP 明确不做）

- 任何后端 / 账号体系 / 数据库（社区为本地模拟，见上）
- 服务端审核与人工复审（客户端过滤只是第一道闸门，见 §6）
- 真实 AI 模型训练或生成（见 §7 预留接口）
- 视频 / GIF 导出
- 评论、关注、私信等重社交功能
- 多语言

## 4. 技术栈与架构

### 4.1 技术栈及理由

| 选型 | 理由 |
| --- | --- |
| Vite + React 19 + TypeScript | 秒级 HMR 迭代快；类型安全约束数据结构（动作/预设/成就/社区作品/审核结果全部强类型）；产物纯静态，可扔任何 CDN / GitHub Pages |
| 原生 Canvas 2D | 像素化 = 缩采样 + `imageSmoothingEnabled=false` 放大，几十行搞定，无需引 WebGL/图像库；分享卡、社区缩略图也是同一个 Canvas 技能树 |
| Web Audio API | 所有音效用振荡器/白噪声现场合成，零音频资源文件，gzip 体积几乎不涨 |
| 手写 CSS（单文件设计系统） | MVP 体量下引 Tailwind/组件库是负资产；用 CSS 变量 + keyframes 完成全部动效，零运行时依赖 |
| localStorage | 最近模板 + 社区 feed + 静音偏好持久化，不需要更重的 IndexedDB |

**零第三方运行时依赖**（只有 react / react-dom）。

数据流：`App` 持有 `view / source / cutout / styleId / resolution / power / care / stickers / cardTemplate`，用 `useMemo` 串起 `cutoutSubject() → pixelate() → analyzeCharacter()` 三段流水线，产物（立绘 / 精灵 / 档案）向下传给舞台、档案面板、出卡工作室与发布弹窗。**内容（文案/预设/词库/贴纸/成就/黑名单/种子）与逻辑完全分离**，运营侧改数据文件即可上新。

### 4.3 像素化管线细节

1. 取源图中心正方形，缩采样到 N×N（N = 16~96，滑杆控制）——即马赛克格。
2. 若预设带调色板：逐像素算亮度 → 映射到"暗→亮"色阶（复古掌机 4 色 / 赛博粉 6 色 / 拓麻液晶 3 色 / 黑白漫画 2 色……），叠加 2×2 Bayer 抖动做颗粒过渡；透明像素保留 alpha。
3. 展示层以 `image-rendering: pixelated` + `imageSmoothingEnabled=false` 硬边缘放大。

## 6. 审核机制设计（发布前强制）

- **入口**：发布弹窗内「提交审核」为发布的前置步骤——按钮态机为 `未审核（发布禁用）→ 审核中 → 通过（发布可用）/ 拒绝（发布禁用 + 原因）`；任何字段被修改立即作废审核结果。
- **检测范围**：标题、作者昵称、一句话简介（后续任何自定义文案字段都走同一入口 `moderateFields`）。
- **黑名单五类**（`src/utils/moderation.ts`，运营可持续追加）：政治敏感、真实公众人物/敏感称呼、侮辱谩骂、低俗色情、违法违规。
- **反绕过**：比对前做归一化——小写化、全角转半角、去空白/标点/零宽字符，拦截"傻 逼""傻·逼"式变体。
- **反馈**：拒绝时逐条列出「字段 × 命中类别」，敏感词打码回显（首字 + `*`），不完整回显。
- **⚠️ 局限性（必须写进上线 checklist）**：这是**客户端启发式过滤**，可被有心人绕过、覆盖面有限，仅作为 MVP 第一道闸门与产品流程验证。正式上线（社区数据进服务端）前必须：接入服务端文本审核 API（政治/色情/暴恐/广告等全量模型）+ 图像机审 + 抽样人工复审 + 举报下架通道；客户端过滤降级为"提前提示"角色。

## 7. 后续迭代路线

1. **真实后端社区**：feed / 点赞 / 点彩 / 配方套用计数上服务端（KV 或轻量 DB），配合服务端审核链路（见 §6）；匿名 id → 可选账号体系；「配方被套用次数」是天然的创作者激励指标。
2. **真实 AI 角色管线**（接口已预留）：三期已把管线拆成 `cutoutSubject()`（主体分割）与 `analyzeCharacter()`（角色识别/人设生成）两个纯函数。接入方式：上传图经服务端（主体分割 → 角色识别 → 风格迁移或 LoRA 角色化），返回透明底立绘 + `CharacterProfile` 结构，替换两个函数返回值即可，下游舞台 / 出卡 / 社区零改动。
3. **养育深化**：数值随时间衰减（`Date.now()` 差值离线结算）、心情影响文案池权重、亲密度解锁隐藏动作 / 隐藏贴纸 / 隐藏卡模板——完整拓麻歌子循环。
4. **动图 / 短视频导出**：用 `canvas.captureStream()` + `MediaRecorder` 把「直戳连击 + 嬷语开麦」过程录成 WebM/GIF，适配抖音/视频号（连击 + 怪声是天然的短视频素材）。
5. **社媒 SDK 与话题运营**：微信 JS-SDK / 小红书分享组件直发；服务端渲染 OG 卡片让链接预览即认证卡。
6. **动作 / 贴纸 / 卡模板商店**：按热点上新（"贴贴""磕头""上香"、节日贴纸包、活动限定卡框），全部数据驱动（`data/` 目录），无需改逻辑。
7. **嬷嬷图鉴与排行**：档案编号（dossierNo）天然是图鉴主键；记录匿名嬷力值榜单与「最多人套用的配方榜」，强化攀比传播。
8. **多角色同台**：两只嬷嬷互摸互怼（嬷语对话），生成 CP 认证卡 / 双人档案卡。
9. **嬷语升级**：为每个体质谱系配专属音节表与语调曲线，长按出「嬷语歌」——怪声内容自身即传播素材。

## 8. 风险与合规

- **版权 / 肖像权**：用户上传内容可能涉及影视截图、真人肖像。MVP 阶段全部处理均在用户浏览器本地完成、不上传不存储（页面与页脚已明示"图片不出浏览器""请只上传你有权使用的图"）。若后续接入服务端社区/AI 管线，必须补充：上传协议确认、投诉下架通道（DMCA 式）、水印溯源。
- **免责声明**：已作为统一组件固定出现在页脚、发布弹窗、社区页顶部，明确「用户 DIY 创作内容由用户自行发布并承担全部责任，与本产品无关，本产品不承担任何责任；请勿上传未经授权的肖像/版权内容；禁止违法及侵害他人权益内容」。上线时需补充完整《用户协议》与《社区公约》页面并在发布流程强制勾选同意。
- **UGC 审核**：MVP 已实现发布前客户端强制审核（五类黑名单），但**客户端过滤不可作为唯一防线**——一旦社区数据进入服务端或对他人可见，必须过机审（文本 + 图像：色情/暴恐/政治敏感）+ 抽样人审 + 举报机制后方可展示。当前社区数据仅存于用户本机 localStorage，不存在跨用户分发，风险敞口可控。
- **未成年人内容**：文案池与种子作品为白名单人工维护，不含性暗示/暴力内容；开放服务端 UGC 时需接入内容安全 API + 青少年模式评估。
- **平台合规**：认证卡属用户自行下载再发布，产品本身不调用社媒发布接口，规避平台 API 政策风险；接 SDK 时再逐平台评审。
- **数值玩法边界**：嬷力值/精力/亲密度为纯娱乐数值，不涉及抽奖/充值/概率公示义务；如未来加入付费道具需另行合规评估。
- **声音体验**：音效默认开启但音量极低（峰值增益 ≤ 0.06）且一键静音持久化；AudioContext 仅在用户手势后创建，符合浏览器自动播放策略。
