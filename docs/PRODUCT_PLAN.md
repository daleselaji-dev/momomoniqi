# 嬷嬷模拟器（momomoniqi）产品实施 Plan

> 把你最严肃的角色，宠成全网嬷嬷。

## 1. 产品定位与改进后的核心玩法

### 1.1 定位

「嬷嬷模拟器」是一个**纯前端的整活式互动玩具**：用户把任何严肃/高冷/威严的角色图（宫斗剧嬷嬷、老板头像、班主任、自家猫）丢进来，系统把它像素化成一只"电子嬷嬷"，然后用摸摸头、rua、拍拍、喂食等动作**过度宠溺**它，收获无厘头反差文案、离谱的"嬷力值"数值和成就，最后一键生成"嬷嬷认证卡"发到社媒。

### 1.2 对初始设想的改进

| 初始设想 | 改进落地 |
| --- | --- |
| "导入角色模板并做动画" | 收敛为**中心裁切 + 像素化 + 调色板风格化**的确定性管线，10 秒内出结果，零后端、零等待，任何图都能出效果（不依赖 AI 生成的不确定性） |
| "支持社媒热点互动（摸摸头）" | 抽象成**动作系统**：4 个动作 × 随机文案池 × 暴击机制，动作可持续追加以蹭新热点 |
| "搞笑元素" | 结构化为三层：**反差文案**（严肃角色被宠到破功）+ **离谱数值**（嬷力值、12% 概率暴击 +66）+ **成就体系**（见习小嬷嬷 → 宇宙第一嬷） |
| "形成爆火效应" | 明确**传播出口**：Canvas 生成的竖版认证卡 PNG（适配小红书/朋友圈 3:4）+ 一键复制带话题标签的文案 |

### 1.3 核心循环（Core Loop）

```
上传角色图 → 像素化/风格化实时预览 → 选动作互动（摸摸头 / rua / 拍拍 / 喂食）
    → 动画 + 无厘头文案 + 嬷力值增长 + 成就 toast
    → 生成"嬷嬷认证卡" PNG / 复制文案 → 发社媒 → 引来新用户上传
```

单次循环 < 60 秒，无注册、无等待，符合"刷到 → 玩到 → 转发"的短链路传播。

## 2. 目标用户与传播机制（为何能爆）

### 2.1 目标用户

- **梗文化重度用户**（小红书 / 微博 / 抖音）：本来就在转发"公公嬷嬷"类魔性内容，需要低门槛的二创工具。
- **粉丝二创群体**：想对自家偶像/角色"下手"但不会 PS/AE 的人。
- **摸鱼社交党**：把老板/同事头像做成嬷嬷卡在群里传播。

### 2.2 传播机制

1. **反差即笑点**：越严肃的原图，被摸头 + "头顶已包浆"文案宠溺后反差越大——用户上传的图本身就是内容燃料，供给无限。
2. **产物自带钩子**：认证卡上有嬷力值、段位、无厘头语录和品牌名，看到卡的人会想"我也要给 XX 办一张"。
3. **数值攀比**：嬷力值、暴击、段位天然形成"晒分"心理；"宇宙第一嬷"是可截图炫耀的社交货币。
4. **热点可插拔**：新梗出现时只需向文案池 / 动作数组加数据（`src/data/quips.ts`），当天即可跟上热点。

## 3. MVP 功能范围 / 非目标

### 3.1 范围内（本仓库已实现）

- 落地首屏（品牌强信号 + CTA + 像素嬷嬷主视觉）
- 图片上传：拖拽 / 点击选择，全程浏览器本地处理
- 像素化管线：颗粒度 16–96 格可调
- 4 种风格预设：像素原味 / 复古掌机 / 赛博粉 / 墨水印
- 互动舞台：4 个动作，各配专属角色形变动画 + 道具入场动画 + 粒子飘散
- 搞笑反馈：每动作 5 条随机文案、12% 暴击（+66 嬷力值 + 专属文案）、5 级成就 toast
- 嬷力值仪表：数值、段位、进度条
- 分享：Canvas 生成 900×1200 认证卡 PNG 下载 + 复制带话题的传播文案
- 最近 3 个角色模板存 localStorage，可一键复用
- 移动端可用（单列布局、动作按钮 2×2）

### 3.2 非目标（MVP 明确不做）

- 任何后端 / 账号体系 / 数据库
- 真实 AI 模型训练或生成（见 §6 预留接口）
- 视频 / GIF 导出
- 排行榜、社区、评论等 UGC 沉淀功能
- 多语言

## 4. 技术栈与架构

### 4.1 技术栈及理由

| 选型 | 理由 |
| --- | --- |
| Vite + React 19 + TypeScript | 秒级 HMR 迭代快；类型安全约束数据结构（动作/预设/成就全部强类型）；产物纯静态，可扔任何 CDN / GitHub Pages |
| 原生 Canvas 2D | 像素化 = 缩采样 + `imageSmoothingEnabled=false` 放大，几十行搞定，无需引 WebGL/图像库；分享卡也是同一个 Canvas 技能树 |
| 手写 CSS（单文件设计系统） | MVP 体量下引 Tailwind/组件库是负资产；用 CSS 变量 + keyframes 完成全部动效，零运行时依赖 |
| localStorage | 最近模板持久化，不需要更重的 IndexedDB |

**零第三方运行时依赖**（只有 react / react-dom），构建产物 gzip 后约 68 KB。

### 4.2 架构

```
src/
├── App.tsx                  # 状态编排：源图、风格、嬷力值、成就、文案
├── types.ts                 # 全部领域类型
├── data/
│   ├── presets.ts           # 风格预设（调色板 + 抖动强度）—— 加风格只改这里
│   └── quips.ts             # 动作、文案池、暴击语录、成就阈值 —— 蹭热点只改这里
├── utils/
│   ├── pixelate.ts          # 像素化管线：中心裁切 → 缩采样 → 亮度色阶映射 + Bayer 抖动
│   ├── defaultMomo.ts       # 内置 20×20 像素嬷嬷（默认角色 & 首屏主视觉）
│   └── shareCard.ts         # 认证卡 Canvas 绘制 + PNG 下载 + 文案拼装
├── hooks/
│   └── useRecentTemplates.ts # localStorage 最近角色
└── components/
    ├── Hero.tsx             # 首屏
    ├── UploadZone.tsx       # 上传区
    ├── StylePanel.tsx       # 风格面板
    ├── Stage.tsx            # 互动舞台（动画 / 粒子 / 动作按钮 / 气泡）
    ├── MomoMeter.tsx        # 嬷力值仪表
    ├── ShareBar.tsx         # 分享栏
    └── Toasts.tsx           # 成就 toast
```

数据流：`App` 持有 `source / styleId / resolution`，用 `useMemo` 走一遍 `pixelate()` 得到小尺寸精灵画布，向下传给舞台（放大展示）与分享卡（放大绘制）。**内容（文案/预设/成就）与逻辑完全分离**，运营侧改数据文件即可上新。

### 4.3 像素化管线细节

1. 取源图中心正方形，缩采样到 N×N（N = 16~96，滑杆控制）——即马赛克格。
2. 若预设带调色板：逐像素算亮度 → 映射到"暗→亮"色阶（复古掌机 4 色 / 赛博粉 6 色 / 墨水印 4 阶），叠加 2×2 Bayer 抖动做颗粒过渡；透明像素保留 alpha。
3. 展示层以 `image-rendering: pixelated` + `imageSmoothingEnabled=false` 硬边缘放大。

| 功能 | 实现位置 | 说明 |

## 6. 后续迭代路线

1. **真实 AI 角色模板管线**（预留接口）：`pixelate(source, …)` 的 `source` 参数已抽象为"任意可绘制图像"。接入方式：上传图先经服务端管线（人脸/主体分割 → 风格迁移或 LoRA 角色化 → 返回透明底立绘），产物直接喂给现有管线，前端零改动。
2. **动图 / 短视频导出**：用 `canvas.captureStream()` + `MediaRecorder` 把互动过程录成 WebM/GIF，适配抖音/视频号。
3. **社媒 SDK 与话题运营**：微信 JS-SDK / 小红书分享组件直发；服务端渲染 OG 卡片让链接预览即认证卡。
4. **动作商店**：按热点上新动作包（"贴贴""磕头""上香"），数据驱动，无需改逻辑。
5. **嬷嬷图鉴与排行**：轻后端（KV 即可）记录匿名嬷力值榜单，强化攀比传播。
6. **多角色同台**：两只嬷嬷互摸，生成 CP 认证卡。

## 7. 风险与合规

- **版权 / 肖像权**：用户上传内容可能涉及影视截图、真人肖像。MVP 阶段全部处理均在用户浏览器本地完成、不上传不存储（页面与页脚已明示"图片不出浏览器""请只上传你有权使用的图"）。若后续接入服务端 AI 管线，必须补充：上传协议确认、投诉下架通道（DMCA 式）、水印溯源。
- **未成年人内容**：文案池为白名单人工维护，不含性暗示/暴力内容；后续开放 UGC 文案时需接入文本审核（如内容安全 API）+ 举报机制。
- **UGC 审核**：一旦增加"分享到站内/排行榜"等任何服务端沉淀，图片必须过机审（色情/暴恐/政治敏感）+ 抽样人审后方可展示；MVP 无服务端沉淀，不涉及。
- **平台合规**：认证卡属用户自行下载再发布，产品本身不调用社媒发布接口，规避平台 API 政策风险；接 SDK 时再逐平台评审。
- **数值玩法边界**：嬷力值为纯娱乐数值，不涉及抽奖/充值/概率公示义务；如未来加入付费道具需另行合规评估。
